Fault log

Every answer that failed verification, with the node that gave it. Three in an hour eject a node for 24 hours. Nothing about who asked is recorded.

—

Opt-outs

Operators who asked to be removed. A node leaves rotation the moment its host publishes /.well-known/mnr-optout (any HTTP 200) or its operator writes to us; the relay reads the file at start and daily.

—

The rules we follow toward these nodes

  1. Disclose. This page, the front page and the User-Agent say what we are.
  2. Contribute. Our own node is a public full node like any other, and it carries the heaviest traffic.
  3. Cap ourselves. At most 5 light requests per second, 2 sync streams and 10 MB/s to any public node; the caps are in the table.
  4. Identify. Every request carries mnr-relay/0.x (+https://mnr.network/upstreams).
  5. Honour opt-out. Publish /.well-known/mnr-optout on your host or write to dev@mnr.network; removal within 24 hours, listed above.
  6. Never pass client identity. No client address, no token, nothing but the RPC body reaches a node.
  7. Restricted RPC only. An allow-list is enforced before anything is sent; we never call admin methods on anyone's node.

Raw data: rpc.mnr.network/upstreams.json. Rules in full: How mnr works.
